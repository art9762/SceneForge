# Запуски, ошибки и продолжение

`current_step` — первый шаг без подтверждённого checkpoint. Он остаётся прежним,
если агент или настройка провайдера завершились ошибкой. `state.run` описывает
последнюю попытку; новая попытка получает новый UUID и сохраняет provider/model.

| `run.status` | Значение | Действие |
| --- | --- | --- |
| `running` | Проект зарезервирован или выполняет текущий шаг | Дождаться результата |
| `waiting_input` | Выполняющийся процесс ждёт выбора концепции | Выбрать концепцию |
| `failed` | Ошибка до подтверждения текущего шага | Проверить настройки и повторить |
| `interrupted` | Процесс остановлен или задача отменена | Продолжить с checkpoint |
| `paused` | Явный `Pipeline.run_step()` завершил отдельный шаг | Продолжить оставшийся pipeline |
| `completed` | Все десять шагов сохранены | Скачать финальные файлы |
| `run = null` | Старый проект без записи запуска | Продолжить явно; прогресс сохранён |

Метаданные попытки: `id`, `provider`, `model`, `step_name`, `started_at`,
`finished_at`, безопасное сообщение `error` и класс `error_type`. В файл/API
не копируется текст исключения провайдера, который может содержать запрос или
служебные данные. Серверный лог может содержать подробности исключения.

## Как продолжить

- Web: открыть прежнюю страницу проекта, нажать «Повторить с сохранённого шага»
  или «Продолжить с сохранённого шага».
- API: `POST /api/projects/{project_dir}/resume` с `{}`. Неуказанные provider/model
  берутся из последней попытки; старый проект использует `claude` и default model.
  Явный JSON `model: null` возвращает default model выбранного провайдера.
- CLI: `sceneforge resume projects/name`. Флаги `--provider` и `--model`
  переопределяют сохранённые настройки.

Ошибки/прерывания не запускаются повторно автоматически при polling или старте
API. Законченные шаги сохраняются. Выбранный человеком concept index записывается
до уведомления очереди; после обрыва resume не спрашивает его заново. Если выбор
ещё не подтверждён, новый процесс восстанавливает ожидание и показывает карточки.
Новый UI отправляет `run_id`; устаревший run получает HTTP 409. Запросы старых
клиентов без `run_id` поддержаны, но не имеют этой проверки поколения.

## Единственный исполнитель

API резервирует проект **до** создания `asyncio.Task`. Файловый `.pipeline.lock`
использует `flock` и удерживается до завершения, ошибки или отмены — включая
ожидание человека. Его содержимое не является признаком активности; важен OS lock.
Тот же lock используют CLI, resume и `run_step`. Конкурентный старт получает 409
в API или ошибку CLI. Другие проекты могут выполняться параллельно.

Обычное завершение API отменяет задачи и сохраняет `interrupted`. После kill или
аварии kernel освобождает lock. Следующий GET state / CLI status получает lock,
обнаруживает оставшийся `running`/`waiting_input` и атомарно отмечает `interrupted`.
Если lock ещё занят другим API/CLI процессом, живой запуск не объявляется мёртвым.
Отмена задачи до её первой инструкции также освобождает резервирование.

`project.json` пишется во временный файл того же каталога, fsync, затем
`os.replace` и fsync каталога. Ошибка до replace сохраняет прошлый checkpoint.
При ошибке шага сохраняется последнее записанное состояние, а не частично
изменённый объект агента. Если файловая система не позволяет записать статус,
последующее чтение после освобождения lock сможет отметить прерывание, но
сохранение сообщения ошибки при отказе хранилища не гарантируется.

## Границы

- Поддерживаются macOS/Linux и локальная файловая система с `flock`/atomic rename.
  NFS, распределённые машины, Windows и старые процессы, не использующие новый
  lock, в эту проверку не входят.
- Для web selection нужен один API-процесс: очереди по-прежнему в памяти.
  Отдельная worker queue / распределённая доставка выбора не реализованы.
- Последняя попытка хранится поверх предыдущей; долговременного журнала всех runs
  пока нет. Старые сгенерированные результаты и UUID проекта сохраняются.
- Незавершённый LLM-запрос может повториться и тарифицироваться повторно.
  Checkpoint не доказывает exactly-once у внешнего провайдера.
- Финальные файлы доступны в UI после полного checkpoint. Возобновление assemble
  повторяет локальную детерминированную сборку, а не вызывает модель.
- Нет публичного cancel endpoint: остановка API/CLI отмечает прерывание.

## Проверки

`tests/test_lifecycle.py` использует fake agents и временные каталоги. Проверены
failure/retry, отсутствие повторного исполнения готовых шагов, конкурирующие
create/resume/CLI, смерть реального subprocess, cancel до старта, shutdown,
потеря процесса после подтверждения выбора, legacy state и отказ atomic replace.
`web/tests/project.spec.ts` проверяет ошибки, resume/conflict, повторный выбор для
нового run и legacy UI в desktop/mobile. Реальные модели не вызываются.
